Small tools win because they are easy to finish.

When scope is tiny, you can iterate quickly and keep quality high.

## My workflow

1. Define one clear input and one output.
2. Add just enough flags to be useful.
3. Ship a first version quickly.
4. Improve only from real usage.

## Common failure mode

The tool starts as a utility, then turns into a framework.

Avoid that.

Keep the core command obvious and the docs short.

## What to document every release

- what changed
- why it changed
- any breaking behavior

This makes future maintenance much easier.
